# 팀 작업 안내

모델 코드는 하나이고(`src/model.py`), 카테고리마다 다른 것은 **옵션값뿐**임.
각자 맡은 카테고리에서 맞는 옵션을 찾아 `CONFIGS` 의 자기 줄에 적는 것이 할 일임.

## 준비 (처음 한 번)

```bash
uv sync
```

`dataset.zip` 을 받아 저장소 폴더에 풀면 `dataset/` 이 생김. `dataset/` 과 `artifacts/` 의 학습 결과는 git 에 올리지 않음.

## 담당

| 담당 | 카테고리 | 함께 맡는 일 |
|---|---|---|
| 백지현 | agri_01부터04, groc_01부터03, med_01부터05 | 모델 통합: `src/model.py` 의 클래스 코드, 전체 38개 실행 |
| 서연 | elec_01부터11, med_06,07 | 임계값: `team.py cv` 결과 확인과 저장 |
| 송유나 | mech_01부터11, med_08,09 | 실험 기록표와 보고서용 사례 그림 모음 |

## 할 일 순서

`example/team_template.ipynb` 를 열고 `CATEGORY` 만 자기 카테고리로 바꿔 위에서부터 실행하면 됨.
노트북은 아무것도 저장하지 않으니 마음껏 돌려도 됨.

1. **전경 마스크 확인** (노트북 2번). 물체가 전부 흰색인지, 결함이 마스크 밖으로 잘리지 않는지 봄. 안 맞으면 `fg_thr` 조정.
2. **학습·채점** (노트북 3번). 카테고리 하나에 몇 분 걸림.
3. **약한 곳 찾기** (노트북 4, 5번). 유형별 점수와, 점수가 높은 정상·낮은 불량의 맵을 봄.
4. **옵션을 하나만 바꿔 다시 실행**하고 바꾸기 전후를 기록표에 적음. 효과가 없었어도 적음.
5. 채택한 옵션을 `src/model.py` 의 `CONFIGS` 에 적고 커밋.

모든 카테고리를 깊게 볼 필요는 없음. 기준 점수가 높은 것은 맵만 확인하고, 같은 도메인의 대표 한두 개에서 찾은 옵션을 나머지에 적용해 본 뒤 안 오르는 것만 따로 볼 것.

## 옵션

| 옵션 | 기본값 | 뜻 | 바꿔 볼 때 |
|---|---|---|---|
| `fg_thr` | 20 | 전경 마스크 밝기 임계값(0~255). `None` 이면 마스크 끔 | 물체 일부가 마스크에서 빠지면 낮춤. 배경 반사광이 들어오면 높임 |
| `aug` | False | 정상 이미지의 회전·뒤집기 사본 8가지를 뱅크에 넣음. 학습이 8배 느려짐 | 물체 방향이 사진마다 제각각일 때만 켬. 방향이 일정하거나 인쇄 방향이 결함인 카테고리(misprint)는 끔. agri_01 에서는 효과가 없었음(AUROC 0.743 → 0.743) |
| `top` | 0.01 | 이미지 점수로 쓸 맵 상위 비율 | 작은 결함을 놓치면 줄임(0.005, 0.002). 정상 점수가 튀면 늘림 |
| `sigma` | 4 | 이상 맵 블러 세기 | 가는 스크래치가 흐려지면 줄임(2) |
| `bank_size` | 20000 | 메모리뱅크 크기 | 드문 정상이 오탐으로 나오면 늘림(40000). 느려지고 파일이 커짐 |

```python
CONFIGS = {
    "elec_04": dict(fg_thr=12),
    "elec_05": dict(fg_thr=12),
}
```

`CONFIGS` 를 고친 뒤에는 그 카테고리를 다시 학습해야 반영됨.

```bash
uv run python main.py train --categories elec_04
```

### 전경 마스크 출발점

38개 카테고리 모두 배경이 어두워서 밝기로 물체를 가를 수 있음. val 결함이 마스크 밖으로 10% 넘게 잘리는 사진 수를 재 본 결과임.

| `fg_thr` | 결함이 잘리는 카테고리 |
|---|---|
| 40 | agri_03·04, groc_01·02, mech_10, elec 10개 등 15개 (elec_04 는 35장 중 23장) |
| 20 (기본) | elec_04, elec_05 각 2장. 나머지 36개는 0장 |
| 12 | elec_04, elec_05 도 0장 → `CONFIGS` 에 반영해 둠 |

결함이 잘리지 않는지만 본 것이고, 배경 반사광이 마스크에 들어오는지는 각자 노트북 2번에서 눈으로 확인할 것.

## 규칙

1. **val 은 뱅크에 넣지 않음.** 옵션과 임계값을 고르는 데만 씀. 한 명이라도 어기면 전체 결과를 쓸 수 없음.
2. **`CONFIGS` 는 자기 카테고리 줄만 고침.** `Model` 클래스 코드와 `folds.csv` 는 건드리지 않음.
3. **한 번에 하나만 바꿈.** 둘을 같이 바꾸면 무엇이 효과였는지 알 수 없음.
4. **작은 차이는 채택하지 않음.** 불량이 카테고리당 9~50장이라 AUROC 0.01~0.02 차이는 우연일 수 있음. 차이가 작으면 기본값을 유지함.
5. **새 기능이 필요하면** `src/model.py` 를 `example/exp_<이름>.py` 로 복사해 거기서 실험하고(노트북의 import 만 바꾸면 됨), 효과를 확인한 뒤 **기본값이 꺼진 옵션**으로 통합 담당에게 넘김.

## 전체 실행과 평가 (통합 담당)

```bash
uv run python main.py train
```

```bash
uv run python main.py eval --out scores.csv --table table.csv
```

```bash
uv run python team.py cv scores.csv --table table.csv
```

마지막 명령이 5-fold 로 임계값 규칙을 평가하고 최종 점수 `(AUROC + F1 + AUPRO) / 3` 을 추정함.

- **F1** 은 fold 밖 판정으로 잼. 각 사진을, 그 사진이 빠진 나머지 4조각으로 정한 임계값으로 판정함. 임계값을 val 에 맞춰 고르기 때문에 이렇게 재야 test 점수에 가까움.
- **AUROC, AUPRO** 는 val 전체 값을 그대로 씀. 임계값처럼 val 에 맞춰 고르는 값이 없어서 나눌 필요가 없음.
- `F1 val맞춤` 열은 임계값을 정한 사진으로 다시 잰 낙관적인 값임. `F1 fold밖` 과의 차이가 과적합 정도임.

임계값 규칙은 두 가지를 비교해서 보여 줌.

| 규칙 | 내용 | 기준 모델에서 fold밖 F1 | val맞춤과의 차이 |
|---|---|---|---|
| 분위수 (기본) | 정상 점수의 상위 q 지점. q 는 전 카테고리 공통 하나 | 0.679 | 0.007 |
| 카테고리별 최적 | 카테고리마다 F1 이 가장 높은 값 | 0.695 | 0.050 |

카테고리별 최적은 0.016 높지만 val 에 맞춘 값과의 차이가 크고(맞추는 값이 38개), 그 정도 차이는 fold 배정에 따라 뒤집힐 수 있어서 맞추는 값이 하나뿐인 분위수 규칙을 기본으로 씀. `--rule per_category` 로 바꿀 수 있음.

제출 전에 임계값을 저장함. val 전체로 정해서 `artifacts/<카테고리>/threshold.txt` 에 쓰고, `load_model` 이 읽어 감.

```bash
uv run python team.py cv scores.csv --save
```

```bash
uv run python main.py check
```

다시 학습하면 점수 눈금이 바뀌므로 그 카테고리의 `threshold.txt` 는 자동으로 지워짐. 그때는 `eval` 과 `cv --save` 를 다시 할 것.

## 주의

- **노트북이 옛 코드를 돌림.** 첫 셀의 `%autoreload 2` 를 지우지 말 것. 의심되면 커널을 재시작.
- **`CONFIGS` 를 고치고 학습을 안 함.** 옵션은 학습할 때 `model.npz` 에 함께 저장되고 채점 때는 저장된 값을 씀.
- **색 눈금에 속음.** 맵은 사진마다 색이 따로 맞춰지면 정상도 빨갛게 보임. 노트북 5번은 공통 눈금으로 그림. 색보다 점수를 볼 것.
- **유형별 숫자를 과신함.** 1~2장뿐인 유형은 한 장 차이로 점수가 크게 바뀜.
